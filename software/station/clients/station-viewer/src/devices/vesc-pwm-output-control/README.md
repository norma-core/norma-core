# Rover operating view

The Cockpit layout replaces the old VESC/PWM dashboard. It retains Station's shared navigation and theme. Desktop has a fixed 300 px control rail which scrolls at short heights. Portrait uses the full width for the square Drive pad and only the rover miniature over video; Camera and Max RPM share one collapsed row. Landscape overlays Drive on the left, Max RPM above it, and the miniature on the right. Only one phone settings editor opens at a time. The shared page uses the dynamic viewport height; portrait video shrinks as browser chrome reduces the available height while Drive stays square. Any necessary overflow stays inside the cockpit. The status bar shows signed Victron battery power (battery voltage × battery current) with two decimals: positive charging, negative drain. All rover loads are wired through Victron LOAD; its battery current already includes that load, so neither load power nor solar power is subtracted again. Missing, erroneous or older-than-5-second snapshots show — W. The tooltip retains battery voltage with two decimals. A stale video frame is marked explicitly instead of silently appearing live. There is no Details panel, Stop button, motion table, or instruction footer.

## Commands

- Drive sends signed VESC `COMM_SET_RPM` (8), exactly as station-pi: forward is negative. The slider controls both pointer and WASD input, initially 4500, selectable range 900–10,000 (matching station-pi’s limit). The rover’s VESC configuration has `s_pid_min_erpm = 900`: active joystick travel maps from 900 to the selected cap in either direction, while the center dead zone and release send exactly zero. This avoids requests below the controller’s speed-mode threshold. These are requested electrical RPM, not measured ground speed.
- While input is held, the latest target is refreshed every 50 ms. Each drive request has a 250 ms duration followed by zero RPM. Pending sends are coalesced; release replaces pending movement with zero. Navigation intent (before lazy route loading), blur, page hide, unmount, target changes, unavailable telemetry and opening settings end driving input. Release is also handled on pointer cancellation or lost capture.
- Steering stays on output `steering`, channel 7, using the existing calibrated 50–130° range. A finite PWM command covers the drive lease; release requests center. The destination is fixed; commands need no PWM status reads.
- Camera targets use output `cameras`, PWM9, held continuously. Slider changes (including dragging and keyboard input) and presets send targets immediately. Only one write is in flight; intermediate pending angles are replaced by the latest target. The final target stays held without further browser commands. Disabling the control or unmounting it drops unsent targets. The calibrated range is −71° (under the wheels) to +270° (2500 µs, rear). The 0° preset is named Reference because its physical viewing direction is not calibrated. The UI reports a target, not servo feedback.

## Live acquisition

`api/live-queue-policy.ts` recognizes a VESC + PWM station from the inference index before reading any payloads. It reads only one VESC inference queue, one USB camera queue, one Nicla Sense ME RX queue and one Victron SmartSolar RX queue. If a type has multiple queues, the first queue name in lexical order is selected consistently. This view currently has no camera/IMU source picker.

Victron reads are limited to 1 Hz. VESC/Nicla reads are coalesced to at most 10 Hz before network I/O. Video follows the selected stream, with no reads while switched Off. Unread sample pointers are not promoted into the payload cache. The inference index itself is still polled at 50 Hz. Queue descriptors are already in that index and identify PWM support without payload reads. PWM commands are sent independently; this view does not monitor PWM status or driver errors. There are no diagnostic subscriptions: raw VESC RX/TX, PWM RX/TX, USB TX, additional Victron devices, system, environment, thermal and other unused payloads are not fetched by this mode. History bypasses this live policy and can inspect all recorded queues; non-rover stations retain the existing acquisition behavior.

## Nicla display

Only full, finite register snapshots with BHY2/rotation validity, a usable quaternion, and timestamps within 1.5 seconds are visualized. Cached connect/error envelopes do not count as fresh samples. A stale/missing sample removes the arrows and heading instead of showing a false level attitude. Acceleration XYZ uses Nicla’s existing linear-acceleration registers (0x38), with gravity removed by firmware; the Acc magnitude and arrow both use these values, so stationary readings are near 0 g. No additional subscription is required. Gyro XYZ shows angular velocity. There is no separate gravity arrow or circular base. Arrows share a deck-center origin and scale logarithmically from zero with magnitude, reaching their capped lengths at 1 g acceleration or 90°/s angular velocity. Arrows shorter than 2 model units are hidden to avoid exaggerating stationary noise. Numeric magnitudes remain unscaled and appear only on desktop/landscape.

The miniature looks forward from behind, with model axes X forward, Y left, Z up. For the mounted Nicla, the display first removes the firmware Euler conversion's 180° X rotation, then maps corrected sensor roll to rover pitch and sensor pitch to rover roll. Positive corrected sensor roll means front raised (nose-up, positive rover pitch); negative sensor pitch means the left side is lowered (negative rover roll). Both the numeric readings and miniature use this mapping. Linear-acceleration and gyro vectors retain their existing axis mapping. No speed integration is performed.

## Validation

Regression tests cover pre-fetch queue filtering versus History, IMU throttling and pointer caching, sensor validity, finite RPM commands, release during a slow send, keyboard RPM limits, suspension/unmount, drive-target handoff, navigation/key-repeat rearming, and steering commands without PWM status. Browser checks use a simulated NormFS transport, so they do not move real hardware.
