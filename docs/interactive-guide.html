NormaCore — Interactive Guide

The unified toolkit for physical system development & operations: what is in this repository, how to build and run it, and how to explore it without any hardware.

What is this repository?

NormaCore combines a unified API, high-performance data pipelines, and visual tooling to manage physical systems as one ecosystem. The pillars:

  • Station (software/station/) — a real-time robotics platform in a single Rust binary: device drivers, the NormFS data layer, an inference pipeline, and an embedded web UI.
  • Hardware (hardware/) — fully 3D-printable machines: the ElRobot 7+1 DoF arm (~$220), a parallel-jaw gripper, and a 5 DoF robotic desk lamp with its own web UI.
  • Gremlin (shared/gremlin_go/, shared/gremlin_py/) — high-performance pure-Go / pure-Python protobuf implementations and code generators used across the stack.
  • SmolVLA (software/ai/smolvla_py/) — fine-tune and deploy a vision-language-action policy on the SO-101 arm.

Quickstart — build & run Station

# builds the web viewer, then the release binary (needs Rust, Node ≥22) make -C software/station/bin/station build # run: NormFS TCP on :8888, web viewer on :8889 ./target/release/station --tcp --web

Open http://localhost:8889. With the bundled station.yaml, the DOGZILLA-Lite driver starts in simulation mode and streams telemetry immediately — no hardware required. Drivers for physical devices (servo bus, cameras, VESC) log warnings until the devices are plugged in. On Linux, add yourself to the dialout group for USB serial access: sudo usermod -a -G dialout $USER.

This guide is grounded in the repository source (verified 2026-11-27). Where the docs and the code disagree, the code wins — and the discrepancy is flagged.

3. Station runtime

Station is one Rust binary that owns the devices, stores every measurement in NormFS queues, runs the inference pipeline, and serves the web viewer. Source: software/station/bin/station/.

Build & run

# native build: viewer (npm ci + build) then cargo build --release -p station make -C software/station/bin/station build # run with defaults: config station.yaml, data in ./station_data ./target/release/station --tcp --web # explicit form ./target/release/station --config station.yaml --normfs-base-folder ./station_data \ --tcp 0.0.0.0:8888 --web 0.0.0.0:8889

Configuration — the bundled station.yaml

drivers: st3215: enabled: true current-threshold: 100 deadband: 20 vesc-trampa: enabled: true port-baud-rate: 115200 system-info: true usb-video: enabled: true resolution: auto # "auto" or "<width>x<height>" resize_target: 224 # resize shortest dimension of stored frames frame-skip: 0 codec: vp8 # or "jpeg" hikmicro-thermal: enabled: false frame-timeout: 5s frame-skip: 0 yahboom-dogzilla-lite: enabled: true mode: simulation # the built-in simulator — see §7 arduino-nicla-sense-me: enabled: true # autodetects USB 2341:0060, ~100 Hz/board inference: - queue-id: inference/normvla shm: /tmp/normvla shm-size-mb: 12 format: normvla st3215-bus: auto update-interval: 100ms

Schema: software/station/shared/station-iface/src/config.rs. Also supported: per-motor motor-current-thresholds, keyframe-interval for VP8 (capped 5 s), and a cloud-offload: S3 section (bucket/region/keys/endpoint/exclude, with AWS_* env fallbacks). Cargo features gate optional drivers: default = ["arduino", "ina226"], plus ov5647 and yahboom-dogzilla-lite.

Queues & the engine

  • Every driver publishes into named queues — e.g. st3215/rx (telemetry), st3215/tx, usbvideo/<md5(unique_id)>, system/rx. Commands go into the commands queue.
  • Per-queue storage policies are set in queue_settings() (src/main.rs): 4 MiB pages for active streams vs 32 KiB for passive ones, zstd compression, AES encryption, fsync per rule; video/thermal skip the WAL.
  • The engine (StationEngine trait in station-iface) registers/unregisters queues and gates snapshots; the inference module maintains inference-states (latest pointer per registered queue) and startups.
  • The web server (hyper + fastwebsockets) hands any WebSocket upgrade to NormFS — the viewer speaks the same queue protocol over WS as TCP clients do.

Cross-compiling for a robot host

# Raspberry Pi (arm64). Needs: cargo install cargo-zigbuild make -C software/station/bin/station build-arm64 # or directly: cargo zigbuild --target aarch64-unknown-linux-gnu --release -p station # with the dog + Pi camera drivers (needs prebuilt libcamera, glibc 2.36/bookworm): make -C shared/libcamera build-libcamera LIBCAMERA_VARIANT=bookworm cargo zigbuild --release -p station --features yahboom-dogzilla-lite,ov5647 \ --target aarch64-unknown-linux-gnu.2.36

AMD64 targets: make build-amd64. On macOS, AMD64 builds need brew install nasm (turbojpeg). The station Makefile's help text claims build builds both architectures — it actually builds the native one only.

5. NormFS & the SDKs

NormFS — the data layer

NormFS is an append-only queue log: writers append entries, readers replay from an offset or follow the tail. Station embeds it (Rust crate normfs 0.4.12); the implementation lives in its own repo (github.com/norma-core/normfs) — what's in this tree is the wire schema (protobufs/normfs/normfs.proto) and the clients.

ConceptWire reality
WriteWriteRequest{write_id, queue_id, packets[]} → WriteResponse{ids[]}. Entries get monotonic ids.
ReadReadRequest{read_id, queue_id, step, offset, limit, accept_encodings} → streamed ReadResponse (RR_START / RR_ENTRY / RR_END / RR_QUEUE_NOT_FOUND), each entry tagged with its source: cloud, disk store, disk WAL, or memory.
OffsetOT_ABSOLUTE (from an id) or OT_SHIFT_FROM_TAIL (N entries back from newest).
EncodingENC_NONE or ENC_ZSTD, negotiated per read.
TransportTCP :8888 and WebSocket :8889 speak the same protocol; setup + ping keepalive.

Gremlin — protobuf, not a connection library

Gremlin is the wire-codec layer: pure-Go and pure-Python protobuf implementations with their own code generators (no protoc). Lazy parsing, null-safe getters, zero-copy reads; the Go README reports up to 23× faster unmarshal than Google protobuf on a Pi 5.

# install the generator go install github.com/norma-core/norma-core/shared/gremlin_go/gremlinc@latest # generate from .proto files gremlinc -src ./proto -out ./generated -module yourmodule/generated
// marshal with the generated struct; read lazily with the generated reader data := user.Marshal() reader := example.NewUserReader() reader.Unmarshal(data) reader.GetProfile().GetFullName() // null-safe, no panic on missing fields reader.ToStruct()

Tests: go test ./... in shared/gremlin_go/. Benchmarks: cd bench && make run-gobench. Runnable example: cd example && make run.

# generate dataclasses + lazy readers from .proto files python3 shared/gremlin_py/gremlin.py --proto-root protobufs/drivers/st3215 \ --target-root target/gen_python/protobuf/st3215 --project-root . \ --gremlin-import-path "shared.gremlin_py.gremlin"

Generated messages expose encode() / encode_to() / calc_protobuf_size(); readers wrap a memoryview with get_*() accessors. Zero runtime dependencies.

Tests: python -m unittest discover -p "*_test.py" in shared/gremlin_py/. The root make protobuf runs both generators over every protobufs/* directory.

Station clients — connecting, following, commanding

The connection libraries live in software/station/shared/station/ (Go) and station_py/ (Python). The station README labels them Work in Progress — the examples below are the in-tree usage patterns.

# connect (default port 8888, auto-reconnect + ping keepalive) client = await new_station_client("localhost", logger) # follow a queue: new entries streamed into an asyncio.Queue as they arrive entries = asyncio.Queue() errq = client.follow("st3215/inference", entries) # or page through history: read_from_tail(queue_id, offset, limit, step, buf_size) # write raw bytes into any queue await client.enqueue("my/queue", payload)
# send a servo command through the commands queue cmd = st3215.Command(target_bus_serial=bus, write=st3215.ST3215WriteCommand(motor_id=1, address=0x2A, value=(2000).to_bytes(2, "little"))) await send_commands(client, [commands.DriverCommand( type=drivers.StationCommandType.STC_ST3215_COMMAND, body=cmd.encode())])

Runnable references: station_py/example_follow.py, example_commands.py. Exports: Client / StationClient, QueueRead, StreamEntry, new_station_client, send_commands.

client := station.NewStationClient("192.168.1.100") // defaults to port 8888 station.SendCommands(client, []*commandspb.DriverCommand{ /* … */ }) // SendCommands enqueues a StationCommandsPack into the "commands" queue

Source: software/station/shared/station/streams.go (wraps normfs.NewClient). A full consumer example: software/station/bin/dataset-generator/.

6. Hardware projects

🦾 ElRobot — 7+1 DoF arm

hardware/elrobot/

Fully 3D-printed, 430 mm reach, ~800 g, ~$220 per arm. Follower: 8× ST3215 12V/30 kg; leader: 8× ST3215 7.4V (low-ratio gears for back-drivability). Waveshare/Seeed bus-servo adapter; 12V/4A follower PSU, 5V/3A leader.

Print: ~320 g PLA leader (13.5 h) + ~360 g follower (16 h); .3mf profiles, STL + STEP, 0.4 mm nozzle / 0.2 mm layers. Assembly: manual-follower.pdf, manual-leader.pdf. SO-ARM100 attribution for handle/trigger/wrist-roll parts.

▸ URDF + STL models: simulation/elrobot_follower.urdf, elrobot_leader.urdf — rendered by the viewer.

🤏 Parallel-jaw gripper

hardware/pgripper/

Modular parallel-jaw gripper, compatible with both SO-101 and ElRobot. 1× ST3215; 27 mm stroke per jaw (54 mm total), ≥4 kg closing force. ~91 g PLA, 4.5 h print; camera-mount variants; STL + STEP, Gripper_ElRobot.pdf manual.

▸ 4 perimeters recommended for STL prints.

💡 Lamp — 5 DoF desk lamp

hardware/lamp/

3D-printed yaw/shoulder/elbow/wrist/head-roll lamp, 5× ST3215 12V (IDs 1–5), ~$140 simple / ~$170 LED version. ~550 g PLA + PETG window, ~19 h; M16-bolt ballast. No end stops on joints 1 & 5.

LED version: XIAO ESP32-S3, WS2812B ring (~48 LEDs), ESP-IDF 5.5 firmware (firmware/esp32-s3/, ./build.sh build / flash monitor, OTA via ./ota.sh).

▸ Web UI: http://nc-lamp.local — sliders, gestures, safe poses, calibration. REST /api/* + MCP at POST /mcp. Optional camera: MJPEG :81 + YOLO11n detector.

# lamp firmware flash (LED version) cd hardware/lamp/firmware/esp32-s3 ./build.sh -p /dev/cu.usbmodem1101 flash monitor # register the lamp's MCP server with Claude Code claude mcp add --transport http lamp http://nc-lamp.local/mcp

7. Simulation & no-hardware demos

🐕 DOGZILLA-Lite simulator — built into Station

The Yahboom driver ships a real kinematic simulator (software/drivers/yahboom-dogzilla-lite/src/sim.rs), enabled by config — and the bundled station.yaml already sets it:

drivers: yahboom-dogzilla-lite: enabled: true mode: simulation # vs real hardware on /dev/ttyAMA0 @115200

What it models: a 20 ms tick; servo positions slewing toward targets at ≤255 units/s (scaled by the speed registers); a trot gait generator (4 leg groups, phase offsets 0/π/0/π, stride 6–28, 0.8–3.0 Hz); yaw integrating into a simulated IMU orientation; battery reported as 100. It publishes the same yahboom-dogzilla-lite/{rx,tx,inference} queues as the real dog, so clients and the viewer work unchanged.

./target/release/station --tcp --web # open http://localhost:8889 → the dog's 3D view (hand-built Three.js model)
Honest limits: simulated telemetry is command echo — there is no real position/current feedback, and the follower has no current sensing. The arm2dog README documents exactly what is and isn't modelled. Great for UI/client development; not a physics ground truth.
🦾 Arm visualization — URDF in the viewer

The web viewer renders ElRobot and SO-101 (leader + follower variants) in 3D from the URDFs in station-viewer/public/devices/, driven by live st3215 telemetry. The same models ship with the hardware: hardware/elrobot/simulation/. There is no ST3215 bus simulator in Station — arm motion simulation with physics is not part of this repo; visualization from telemetry is.

# viewer dev mode against a running station cd software/station/clients/station-viewer npm ci && npm run dev # http://localhost:5173
💡 Lamp browser simulation

The lamp ships a URDF + a standalone browser viewer — no firmware or hardware needed:

cd hardware/lamp/simulation python -m http.server 8000 # then open viewer.html
🔁 arm2dog — drive the simulated dog with a leader arm

software/station/examples/arm2dog-py/ maps ElRobot leader joints onto the dog's arm servos (ids 51/52/53) plus movement axes, across two stations. With the dog station in simulation mode, the follower side needs no hardware:

uv run python main.py --leader-server 192.168.68.66 --follower-server 192.168.68.56 \ --map "8:51:inv,6:52,4:53" --yaw-leader-id 1 --fwd-leader-id 2 # or a YAML mapping: uv run python main.py --config configs/three-axes-test.yaml

Read its README's safety section first: command-echo telemetry, no follower current sensing, no torque-disable path.

Record → export → train → deploy (SmolVLA on SO-101)

1
Record — in the web viewer, create start/end Tags around episodes (default 45 s, min 5 s between, 8 s reset recommended). Copy frame numbers from the History page. Full guide: docs/datasets/export-parquet/datasets-export.md.
2
Export — the dataset tools cut parquet episodes from the queues; preview as mp4.
./dataset-generator -episode.duration 35 -from 18979274 -to 22445334 \ -robot 192.168.0.10 -output ~/datasets/dataset-cube -task "put the cube inside box" ./dataset-mp4 --input ~/datasets/dataset-cube.parquet --output ~/datasets/dataset-cube.mp4
3
Fine-tune — SmolVLA (lerobot/smolvla_base) on the parquets.
cd software/ai/smolvla_py && uv sync uv run python scripts/train.py --steps 30000 --batch-size 64 \ --parquets path/to/dataset.parquet --output checkpoints/run # merge several datasets first if needed: uv run python scripts/merge_datasets.py --inputs path/to/dataset-*.parquet --output merged.parquet
4
Deploy — run the policy on the arm's machine; it reads frames from inference/normvla.
# interactive: SPACE advances one tick uv run python scripts/run_policy.py --checkpoint checkpoints/run/final \ --task "place the yellow cube on top of the other" --bus-serial 5AB9068807 --max-delta-ticks 512 # continuous: uv run python scripts/run_policy.py --checkpoint checkpoints/run/final --auto --max-ticks 200 …
Remote training: ./scripts/build_bundle.sh dataset.parquet → smolvla-bundle.zip; full Nebius serverless recipe in nebius.md.
